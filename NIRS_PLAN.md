# НИРС — план и анализ

Состояние от 2026-06-04. План научно-исследовательской работы студента (НИРС)
под проект `cfd-platform`, по образцу НИРС Бердышева К.Д. (РК6, 2026). Пара к
[PRACTICE_REPORT_PLAN.md](PRACTICE_REPORT_PLAN.md) (практика) и
[PRACTICE_REPORT_ARCHITECTURE.md](PRACTICE_REPORT_ARCHITECTURE.md).

## Ключевое наблюдение из примера Бердышева

Его НИРС — **глубокая теоретико-методическая разработка**, НЕ система и НЕ
результаты. Состав: формальная постановка (k-NN, метрики), разбор алгоритма
(HNSW — псевдокод + математика), разбор модели (ViT/SigLIP — полная математика
прямого прохода), анализ техники-фокуса ВКР (оптимизация TensorRT). **В НИРС
нет ни одного эксперимента, числа Recall@k или замера латентности** — только
теория, формулы и псевдокод. Эмпирика — в ВКР.

→ Жанр НИРС на РК-6 = «формализовать и глубоко разобрать научную сердцевину
работы и методы, лежащие в её основе», с математикой и псевдокодом, **без
измеренных результатов**.

## Триада документов (как делится материал)

| Документ | Жанр | Что внутри | Главы ВКР |
|---|---|---|---|
| **Отчёт по практике** | инженерия | как **построена** платформа (backend, extender, extraction, образы, кластер, smoke) | 3–4 |
| **НИРС** (этот план) | теория/методы | формальная постановка (QAP), разбор алгоритмов размещения (псевдокод), методология извлечения F-графа, методология оценки. **Без чисел.** | 1–2 + методология 5 |
| **ВКР / диплом** | всё вместе | практика + НИРС + **эксперимент и результаты** (Table 5.1, графики, p-value) + выводы | все |

Один и тот же компонент попадает в практику и в НИРС под **разными углами**:
- *Планировщик:* практика — «extender, 3 алгоритма, маршрутизация по лейблу,
  деплой»; НИРС — вывод QAP, математика и псевдокод Müller-Merbach, сложность,
  теоретическое обоснование.
Дублирования почти нет — линзы разные (инженерия vs теория).

## Что НЕ включать в НИРС (это в ВКР)

- Численные результаты, Table 5.1, графики gain(ρ), p-value конкретных прогонов.
- Подтверждение/опровержение гипотезы по данным.
Можно (и нужно) описать **методологию** эксперимента и **гипотезу как
формулировку** — но не её эмпирическую проверку.

## Рекомендуемая структура НИРС (под cfd-platform)

Объём-ориентир: ~22–26 стр. (у Бердышева 24). Много формул + 2–3 листинга
псевдокода. Титул как у Бердышева. Тема (research-флейвор, под фокус ВКР):

> «Исследование методов topology-aware размещения тесно-связанных MPI-задач
> в кластере Kubernetes на основе квадратичной задачи о назначениях»

### Аннотация + ключевые слова
QAP, размещение процессов, MPI, communication graph, topology-aware scheduling,
Kubernetes scheduler extender, Müller-Merbach, доменная декомпозиция, mpiP,
multi-AZ latency. Объект: размещение MPI-рангов по узлам. Предмет: модель
размещения как QAP, эвристики (greedy, Müller-Merbach), методология извлечения
графа коммуникации и оценки.

### Введение (~2 стр.)
Актуальность: рост инженерных расчётов (CFD/FEM) → MPI на K8s; топологическая
слепота стандартного планировщика; коммуникационные задержки в multi-AZ.
Объект/предмет/цель/задачи (формализация → алгоритмы → методология извлечения
→ методология оценки). Без результатов.

### 1. Постановка задачи размещения MPI-рангов (~4–5 стр.)
- **1.1** Тесно-связанные MPI-вычисления и амплификация синхронизации: на
  коллективах (`MPI_Allreduce`) все ранги ждут самого медленного; задержка на
  одном ребре каскадирует (теоретическая мотивация — Hoefler 2010).
- **1.2** Формальная модель: доменная декомпозиция → граф коммуникации
  F = (V_ranks, w_ij); матрица латентности узлов L(a,b); размещение π: ранги→узлы;
  целевая функция **C(π) = Σᵢⱼ F(i,j)·L(π(i),π(j))** → минимизировать.
- **1.3** Связь с **квадратичной задачей о назначениях (QAP)** в форме
  Купманса–Бекмана; NP-трудность и отсутствие константного приближения
  (Sahni–Gonzalez) → обоснование эвристик.
- **1.4** Метрика качества размещения: суммарное MPI-время (источник — профиль
  mpiP); связь с C(π).
→ формулы из `scheduler/algorithms/types.go` (`Cost`), [THESIS.md](THESIS.md) гл.2.

### 2. Алгоритмы размещения рангов по узлам (~6–7 стр.) — ЯДРО (как глава HNSW у Бердышева)
- **2.1** Точное решение QAP (ветвей и границ) и его неприменимость при росте N.
- **2.2** Случайное размещение (baseline, «без topology-awareness»):
  воспроизводимость через детерминированный seed (FNV-1a от jobID). Псевдокод.
- **2.3** Жадный онлайн-алгоритм: размещение нового ранга на узел,
  минимизирующий частичную стоимость связи с уже размещёнными; сложность
  O(n²). **Псевдокод** (из `greedy.go`).
- **2.4** Эвристика **Müller-Merbach** (офлайн, конструктивная с каскадными
  переназначениями, по Burkard/Dell'Amico/Martello §8.2.1): порядок по убыванию
  суммы строки F; полная Δ-стоимость кандидата с учётом вытеснения; сложность
  O(n²·M); кэширование полного размещения на задачу. **Псевдокод + разбор**
  (из `mueller_merbach.go`).
- **2.5** Сопоставление свойств алгоритмов (онлайн/офлайн, отказоустойчивость,
  ожидаемое качество при росте плотности F) — теоретически, без чисел.
→ листинги: `Cost()` + псевдокод Müller-Merbach.

### 3. Извлечение графа коммуникации из декомпозиции решателей (~5 стр.) — методический вклад
- **3.1** Три класса коммуникационных паттернов: sparse FVM (OpenFOAM, обмен
  по геометрическим соседям), explicit FEM (OpenRadioss, граничные узлы),
  implicit FEM с MUMPS (Code_Aster, плотный fill-in).
- **3.2** Единая методология: w(i,j) извлекается из артефактов **доменной
  декомпозиции** до запуска (без инструментирования MPI):
  - OpenFOAM: `decomposePar` → `processor*/polyMesh/boundary`, w = nFaces;
  - OpenRadioss: METIS-граф (sed-патч) → `gpmetis` → разбиение;
  - Code_Aster: `medpartitioner` joints (MEDLoader) → w = число общих узлов.
- **3.3** Формат графа и его свойства (симметричная разрежённая F, плотность ρ
  как характеристика задачи).
→ формализация из [EXTRACTION.md](EXTRACTION.md); это уникальная часть.

### 4. Методология экспериментальной оценки (~5 стр.) — МЕТОД, не результаты
- **4.1** Воспроизводимая эмуляция multi-AZ: Linux `tc qdisc netem`, логические
  зоны, контролируемый контраст латентности; обоснование как стандартной
  академической методологии.
- **4.2** Измеряемая величина: суммарное MPI-время из mpiP (LD_PRELOAD),
  что и почему.
- **4.3** Обоснование числа рангов N и гранулярности per rank по литературным
  порогам (OpenFOAM/LS-DYNA/MUMPS) — как **проектное обоснование** методики.
- **4.4** Статистический аппарат: Shapiro-Wilk (нормальность) → доверительный
  интервал (Student-t / перцентильный bootstrap) → парные сравнения
  (paired t-test / Wilcoxon), односторонние при направленной гипотезе.
- **4.5** Гипотеза исследования (как формулировка H1/H2) и угрозы валидности —
  **без эмпирической проверки** (она в ВКР).
→ из [EXPERIMENT.md](EXPERIMENT.md); описывать как методологию.

### Заключение (~1–2 стр.)
Сформирована формальная модель размещения как QAP; разобраны алгоритмы
(random/greedy/Müller-Merbach) с псевдокодом и оценкой сложности;
формализована методология извлечения F-графа для трёх классов решателей;
обоснована методология экспериментальной оценки. Результаты НИРС —
теоретико-методическая основа эмпирического исследования в ВКР.

## Итог (ответ на «что в НИРС»)

- НИРС = **теория и методы**, формализованные (математика + псевдокод), как у
  Бердышева. **Без эксперимента и чисел** — они в ВКР.
- Сердцевина — **глава 2 (алгоритмы размещения, QAP)**: это твой алгоритмический
  вклад, разбери Müller-Merbach с псевдокодом и сложностью так же подробно, как
  Бердышев разобрал HNSW.
- Вторая сильная часть — **глава 3 (методология извлечения F-графа)**.
- Границы: система/деплой → практика; численные результаты → ВКР.
- Для НИРС тоже можно сделать writer-промпт (как `PRACTICE_REPORT_WRITER_PROMPT.md`)
  + архитектурно-математический бриф — скажи, подготовлю.
