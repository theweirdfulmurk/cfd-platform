# Промпт для Claude-писателя НИРС

Скопируй тело (между линиями) в свежую сессию Claude, запущенную **в корне репо
`cfd-platform`**. Файлы `NIRS_MATH_BRIEF.md`, `NIRS_PLAN.md` и код должны быть
доступны.

---

Ты пишешь **научно-исследовательскую работу студента (НИРС)** для проекта
`cfd-platform` — это теоретико-методическая часть дипломной работы студента РК-6
МГТУ им. Баумана (тема ВКР — topology-aware Kubernetes-планировщик для
параллельных инженерных расчётов). Жанр НИРС = **глубокая теория и методы,
формализованные** (математика + псевдокод); измеренных результатов в НИРС нет —
они в ВКР.

## Сначала изучи (в этом порядке)
1. `NIRS_MATH_BRIEF.md` — формальная модель, нумерованные формулы, псевдокод
   алгоритмов по фактическому коду, методология, источники по главам. Главный
   источник.
2. `NIRS_PLAN.md` — структура глав и граница «НИРС vs практика vs ВКР».
3. **Код** `scheduler/algorithms/*.go`, `pkg/decomp/` — первоисточник для
   псевдокода/формул; сверяй каждый шаг алгоритма с кодом, ничего не выдумывай.
4. Вспомогательно: `EXTRACTION.md` (гл.3), `EXPERIMENT.md` + `RELATED_WORK.md`
   (гл.4 — как методология, не результаты).

## Что написать
Один markdown-файл `NIRS.md`, на русском, академический стиль (как в типовых
НИРС РК-6: нумерованные формулы, листинги псевдокода с подписью «Листинг N – …»).
Объём ~22–26 страниц. Титул/аннотация/ключевые слова — как в примере.

Тема: «Исследование методов topology-aware размещения тесно-связанных
MPI-задач в кластере Kubernetes на основе квадратичной задачи о назначениях».

Структура (по `NIRS_PLAN.md`):
- **Введение** (актуальность, объект/предмет/цель/задачи; без результатов).
- **Глава 1. Постановка задачи размещения** (мотивация — амплификация
  синхронизации; формальная модель F, L, π; целевая функция C(π) — формула (1);
  связь с QAP и NP-трудность; плотность ρ; метрика — MPI-время).
- **Глава 2. Алгоритмы размещения рангов** ← ЯДРО, как глава HNSW у Бердышева:
  точное решение и его пределы; random (baseline); greedy (O(n²)); **Müller-Merbach**
  (псевдокод + формулы (6)–(8) + сложность O(n²·M) + каскад); сопоставление свойств.
- **Глава 3. Извлечение графа коммуникации** (3 класса решателей; единый
  pipeline; w(i,j) на класс; свойства F).
- **Глава 4. Методология экспериментальной оценки** (mpiP/MPI-время; multi-AZ
  через tc netem; обоснование N/гранулярности; статистика — Шапиро-Уилк → t-CI/
  bootstrap → парные тесты; гипотеза как формулировка). **Метод, не результаты.**
- **Заключение** (что формализовано/разобрано; НИРС как основа эмпирики в ВКР).
- **Список использованных источников** (только реально процитированные).

Дай больше глубины **главе 2** (алгоритмы/QAP — разбери Müller-Merbach так же
подробно, как Бердышев разобрал HNSW) и **главе 3** (извлечение F). Включи
**2–3 листинга псевдокода** из Части F брифа.

## Жёсткие ограничения (нарушение = переписывать)
1. **Без эмпирики**: никаких численных результатов, Table, графиков gain(ρ),
   p-value конкретных прогонов, подтверждения/опровержения гипотезы по данным.
   Гипотезу и методологию излагать как формулировку/метод.
2. **Без инженерии/деплоя**: backend/chi, Docker-образы, CI, cluster-up, kind,
   mpi-operator-как-сервис, frontend, PVC — НЕ сюда (это отчёт по практике).
   Здесь — формализм, алгоритмы, методология. (mpiP и tc netem упоминать только
   как метод измерения/эмуляции в гл.4.)
3. **Псевдокод и формулы — по коду**: сверяй с `scheduler/algorithms/`; шаги,
   стоимости (5)/(7)/(8), порядок (6), сложности — как в брифе/коде.
4. **Источники — только реальные** из Части E брифа; в список — лишь
   процитированные. Не выдумывать ссылки и не приписывать чужие результаты.
5. **Локализация имён и аббревиатур.**
   - Фамилии людей в тексте — **кириллицей** (Мюллер-Мербах, Купманс, Бекман,
     Буркард, Карипис, Хофлер, Се (Xie); «эвристика Мюллера-Мербаха», «по
     Буркарду, Дель’Амико и Мартелло»). СПИСОК ИСТОЧНИКОВ — в оригинале
     (латиница, как для иноязычных по ГОСТ).
   - Аббревиатуры с **устоявшимся русским стандартом — русифицировать**:
     FEM → **МКЭ** (метод конечных элементов), CFD → **ВГД** (вычислительная
     гидродинамика).
   - Международные акронимы **без русского стандарта — оставлять латиницей** с
     русской расшифровкой при первом упоминании: QAP («квадратичная задача о
     назначениях (QAP)»), MPI, HNSW, MUMPS. **Не выдумывать** русские сокращения
     (никаких «КЗН»).
   - Названия технологий/продуктов/идентификаторов (Kubernetes, mpiP, OpenFOAM,
     MPIJob, Go) — латиницей; имена процедур в псевдокоде — латиницей (это код).

## Типичные ошибки, которых избегай
- Протащить численные результаты/Table «для убедительности» — это ВКР.
- Скатиться в описание системы/деплоя (это практика) вместо теории/алгоритмов.
- Исказить псевдокод Müller-Merbach (особенно каскад вытеснения и формулу (8)) —
  сверяйся с `mueller_merbach.go`.
- Английский там, где уместен русский (кроме имён: QAP, MPI, Kubernetes, HNSW нет).
- Голословные формулы без вывода/смысла — у каждой формулы поясняй величины.

Пиши «на чистовик»: НИРС переносится в главы 1–2 ВКР + методологию главы 5.
